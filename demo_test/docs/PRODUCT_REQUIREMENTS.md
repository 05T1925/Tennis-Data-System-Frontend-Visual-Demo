# 产品需求

Status: Baseline Draft  
Version: v0.1

## 1. 项目背景与阶段定位

网球视频分析系统 v0.1 用于验证从用户上传网球视频到展示可理解分析结果的数据闭环。当前是原型阶段，首要目标是闭环和可演示性，而不是高精度算法或正式上架。

## 2. 用户、场景与痛点

### 2.1 目标用户

- 普通网球用户：希望了解一次训练或比赛视频中的基础数据与分析结论。
- 团队成员：需要查看任务执行、CV 原始输出、结构化数据和失败原因。

### 2.2 用户场景

用户上传网球视频后，等待并查看分析进度，再阅读结果与统计。团队通过 Web Dashboard 排查上传、任务或数据处理异常。

### 2.3 用户痛点

- 视频分析过程不可见，用户不知道是否正在处理或为什么失败。
- 原始算法数据难以直接理解。
- 团队缺少统一入口来调试和演示完整链路。

## 3. v0.1 目标与范围

### 3.1 目标

- App 具备基本产品形态，而不只是代码 Demo。
- 用户能完成身份获取、上传视频、查看视频列表和分析状态、查看结果与统计。
- Web Dashboard 能辅助团队查看视频、任务、CV 输出、结构化结果、统计和失败原因。

### 3.2 App 功能范围

- 登录或简单用户身份。
- 视频上传，并展示上传进度。
- 视频列表与单个视频详情入口。
- 分析状态、当前阶段与失败原因展示。
- 分析结果、击球/回合/得分点的可理解展示。
- 面向普通用户的基础统计。

### 3.3 Web Dashboard 功能范围

- 查看上传视频与分析任务。
- 查看 CV 原始输出和结构化分析结果。
- 查看统计数据与失败原因。
- 服务开发、调试和演示；不作为面向普通用户的正式产品。

### 3.4 服务端边界

Backend 计划负责身份、视频存储、任务管理、权限和 REST API。CV Module 计划输出识别原始数据。Data Processing 计划将原始数据提取为 Shot、Rally、Point 与统计。

## 4. 核心用户流程

```text
获得身份 → 选择并上传视频 → 查看上传进度 → 创建分析任务
→ 查看分析状态/失败原因 → 查看分析结果与统计
```

## 5. 体验与状态要求

- 上传必须有可见进度、成功、失败与可恢复提示。
- 分析必须显示状态与阶段；失败必须说明可展示的原因。
- 每个主要页面应覆盖 loading、empty、error、success 状态。
- 普通用户应能理解结果含义，不要求阅读 CV 原始数据。
- 错误信息不得暴露密钥、内部堆栈或隐私数据。

## 6. 初步非功能要求

- 结果页面应在数据未完整时安全降级显示。
- 大视频、模型权重、数据集和隐私数据不进入 Git。
- 性能指标、视频格式限制和数据保留策略均待确认。

## 7. v0.1 不做内容

- 正式应用商店发布。
- 高精度算法承诺。
- 完整社交、支付、赛事或教练体系。
- 将 Web Dashboard 作为用户正式产品。
- 在阶段 0 创建脚手架、代码、接口或依赖。

## 8. 验收标准

- 用户可完成原型闭环中的上传、状态查看和结果查看。
- 上传有进度，分析有状态，失败有原因。
- App 与 Web Dashboard 的边界清晰。
- 统计数据与原始 CV 输出可被明确区分。
- v0.1 首要验证数据闭环，而非算法精度。

## 9. 已确认假设

- App 是面向普通用户的主要产品形态。
- Web Dashboard 仅面向内部团队。
- 初期计划以 Mock Service 先验证前端流程，再切换到相同接口的 Real Service。

## 10. 待确认事项

- 身份认证方式、视频存储与上传策略。
- 真实 CV 输出字段与置信度定义。
- 视频格式、大小、时长和隐私策略。
- 最终统计指标、性能目标与 API 权限模型。

## 11. 后续版本候选能力

- 更细粒度击球与战术分析。
- 结果对比、趋势、分享和教练协作。
- 更完整的异常重试与通知机制。
